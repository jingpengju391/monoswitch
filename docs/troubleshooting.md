# 故障排查

## 找不到本地程序

使用 Chrome / Chromium 123 或更新版本，在扩展引导页点击「下载组件」。下载完成后，Windows 点击「打开安装器」；macOS 点击「解压安装包」，再打开解压后的 `Install MonoSwitch.app`；Linux / Manjaro 直接下载 `Install MonoSwitch.run`，在文件属性中允许执行后双击，或复制扩展提供的启动命令，按需确认系统授权。完成安装后引导页会自动连接。只加载 Chrome 扩展并不会自动安装本地组件。若引导页没有当前系统的安装包，请使用包含对应平台安装器的完整发行扩展。

重新打开引导页会恢复已有下载记录；下载中断或文件已删除时可重试。若按钮无法打开文件，点击「在文件夹中显示」。Linux 直接下载程序；Chrome 下载的文件需先允许执行。安装器自动配置依赖、模块和视频设备权限，无需逐条复制系统命令。没有图形授权代理时，可从终端运行安装器使用 sudo 授权；无需以 root 运行 Chrome。Windows / macOS 的系统安全确认仍需用户处理。

判断安装成功：安装引导消失，出现系统信息和显示器设置；自动检测连接时会提示「本地组件已连接」。打开文件、解压 ZIP 或复制命令不代表安装完成。如果连接后提示缺少 ddcutil，说明组件安装成功，但显示器控制依赖尚未满足。

开发者可先 `npm run build`，再 `npm run setup`，重新打开扩展点击刷新。JS 开发安装脚本会打印扩展 ID 与注册文件路径；应与 `chrome://extensions` 所显示的 ID 一致。

通过 `npm run setup -- --dry-run` 查看计划写入的位置；通过 `--extension-id` 匹配自行发布的扩展。项目目录含中文或空格也可使用，安装器将程序复制到当前用户的固定应用目录。更新本地程序后需再次执行 setup。

自定义 Chrome `--user-data-dir`、Flatpak/Snap 沙箱浏览器、企业策略禁用 nativeMessaging 的环境可能需要额外浏览器配置。默认安装针对普通桌面版 Chrome/Chromium 的默认用户数据目录。

## Linux 没有检测到显示器 / 权限不足

先点击扩展中的「自动配置」。旧版本若显示「更新本地组件」，先运行新版安装器。自动配置会按需安装 ddcutil、加载 i2c-dev、设置开机加载并刷新 uaccess 权限。系统授权取消或安装失败会显示原因，允许重试。若配置完成仍无法检测，检查显示器的 DDC/CI 开关和接线；笔记本内置屏幕不支持该切换功能。

以下为手动排错步骤：

1. 确认显示器菜单里的 DDC/CI 已开启。
2. 安装 `ddcutil`，用 `sudo modprobe i2c-dev` 加载内核模块。
3. 在当前桌面会话中，以普通用户运行 `ddcutil detect`。先解决它报告的设备访问问题。
4. 确认发行版安装了 ddcutil 的 `60-ddcutil-i2c.rules`。注销再登录，让用户会话权限生效。
5. 尽可能直连显示器。扩展坞、转换器、部分显卡驱动可能阻断 DDC。

不建议给所有用户开放全部 I²C 设备的写权限。参考 [ddcutil 的 I²C 权限说明](https://www.ddcutil.com/i2c_permissions/) 和 [内核模块配置](https://www.ddcutil.com/kernel_module/)。Manjaro 使用同一 Linux 后端，读取 `/etc/os-release` 显示发行版名称。

## macOS 找不到控制后端

确保 BetterDisplay 已安装并正在运行，在设置中开启 CLI / Notification 集成和显示器 DDC 控制。程序自动查找 `/Applications/BetterDisplay.app` 或当前用户 `Applications` 下的应用内置 CLI，无需单独安装命令行工具。如果已安装独立 `betterdisplaycli`，也会检查 PATH 与常见 Homebrew 目录。详细命令见 [BetterDisplay CLI 文档](https://betterdisplay.pro/guide/integration/cli-reference/)。

如果 BetterDisplay 本身不能对该显示器读取/设置输入源，MonoSwitch 也不能。Intel 与 Apple Silicon 的显示器链路支持并不完全相同；请在 BetterDisplay 内验证当前连接。

## 能读亮度，但不能切输入

DDC/CI 支持是按功能区分的。输入切换使用 VCP `0x60`，与亮度控制不同。当前版本要求显示器能响应输入源查询；仅可写而不可读的型号暂不支持。某些显示器需要厂商私有命令；当前版本不尝试猜测和写入私有 VCP。未报告输入能力时，标准输入列表只是候选，须按显示器实际连接确认。

## 切过去后不能切回来

部分显示器只接受当前输入口发出的 DDC 命令。请在另一台电脑上也完成安装和配对，并从当前显示的电脑操作。快捷键只对收到该按键的电脑生效，不会自动转移键盘或鼠标。

若目标电脑未开机、休眠或没有输出视频，显示器可能黑屏或自动切回。可先用显示器实体菜单恢复输入，再确认对端状态。

## 对端系统显示不对 / 显示器不匹配

对端系统来自它自己的配对码。重装系统、更换显示器/接线后重新交换配对码。DDC 不提供网络发现或对端系统检测；同一型号的两台显示器也可能没有可用序列号，需核对共享显示器与接口。

## 安全与隐私

扩展申请 `nativeMessaging`、`storage`、`downloads` 和 `downloads.open` 权限。下载权限用于组件下载、状态恢复，以及用户点击后打开文件或显示所在文件夹。扩展不读取网页、不注入内容脚本、不上传设备信息。配对码是设备描述，不是登录凭据，也不赋予远程控制权限。设置留在各电脑本地，不使用 Chrome 同步来覆盖另一台电脑的本机输入配置。安装器只允许固定扩展 ID 连接本地程序；本地程序只处理受限的显示器查询、输入切换及固定 Linux 系统配置请求。系统配置必须由用户明确启动，并通过系统授权工具确认，不能传入任意命令。

## 键鼠共享

- 两台一直等待：旧版默认都可能是发送端。更新两边组件，停止旧共享；Type-C 那台生成配对码，HDMI 那台输入并连接，不要在两边都生成配对码。
- 不知道是否成功：先显示「等待另一台输入配对码」，成功后显示「已连接，可以切换」。此时直接使用主界面切换电脑。
- 无法生成配对码：先选本机显示器与输入接口，安装 Deskflow，确认局域网 IPv4 可用。不要同时运行另一套 Deskflow 会话。
- 无法连接：两台需在可互通的局域网，发送端允许 TCP 24800 和 24801，配对码五分钟有效；失效后重新生成。VPN、访客 Wi-Fi 或网络隔离可能阻止连接。
- 切换失败：按钮会先检查键鼠焦点是否成功，再切画面。X11 是当前已验证的 Linux 发送端；Wayland 暂不支持按钮联动。macOS 本地组件和 Deskflow 均可能需要输入权限；Windows 锁屏、UAC 安全桌面和提权窗口不保证可控。
- 键鼠切换但画面没切：确认本机/对端输入接口设置和显示器 DDC/CI 支持，部分显示器不接受非当前输入端口的 DDC 指令。显示器实体按钮切画面不会联动软件键鼠。
- 关闭共享：点击「停止键鼠共享」会结束本机共享并关闭自动恢复。两边 Chrome 需运行，发送端不能休眠。
